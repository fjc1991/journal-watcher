# Changelog

Release notes: `.github/workflows/release.yml` reads the bullets under the heading of the version being released (`## 1.2.0`) and shows them in the app's "Update available" dialog.

## 1.2.4

- **Fixed: Change data folder… did nothing.** Choosing another folder (Data → Change data folder…) saved the choice and started the app again, but the new copy came back on the old folder every time, or ran into the old copy's lock ("already open for this folder"). The app passes its data folder to its own modules through the environment, and the restarted copy inherited that setting and preferred it to the folder you had just chosen. The restart now leaves it out.
- **Change data folder… can take your data along.** After you choose the folder, the app asks: copy your papers, notes, folders, settings and API keys there first, or switch without copying. The copy never changes the old folder (it stays as it is until you delete it yourself) and the page says what was copied. When the new folder already holds Journal Watcher data (a Dropbox folder in use on another computer, say), what is already there is kept: a file that exists in both places keeps the new folder's copy, the settings files included, and the two library lists are joined so that no paper is lost. What belongs to one computer (the sign-in browser, caches, update state) is not copied. The same button is now in Settings → About & updates, next to "Your data lives in …".
- **A first start finds the folder an earlier version used.** With nothing chosen yet, the app looks for `~/Documents/Journal Watcher` (and the folder a personal build was made for) and offers to keep using it or to move it to a folder you choose, with the same copy as above.

## 1.2.2

- **Ask about one chapter, and a summary of one chapter on request.** In a book's Chapters list, **Ask about it** opens the book in the reader on the Ask tab with that chapter chosen: the model reads only those pages, and the answer's sources say “Chapter 3 · p. 48” (or “location 57” in an EPUB) and that only the chapter was read. A book's Ask tab has a chooser (Whole book or any chapter) and asking again keeps the chapter the first answer used. **Summarise…** shows what it would do and what it costs first (how many pages go to which provider and model, and the cost; a very long chapter is read from its start and its end and the summary says the middle was left out) and writes nothing until you press **Write the summary**. It is one request through the same budget and usage record as every other AI call. The summary says its pages the way the rest of the app does, is kept with the book (so clearing the AI's answer cache does not make it cost again), and can be written again on request. Books are still never summarised by themselves.
- **Book chapters and page numbers.** Every book row has a **Chapters** button: the chapters and sections from the book's own outline (an EPUB's table of contents, a PDF's bookmarks), each with **Open** (the reader opens the book at that page) and, on the Books tab, **Search in it**: type words, press “In the books”, and they are looked for only inside that part of that book (a chapter runs to the page where the next one starts, and that page counts for both, so nothing at the top of it is lost). Hits are named the way you could cite them: “Chapter 3 · p. 48” for a PDF book once you say where printed page 1 is (**Printed page 1 is file page …**, saved per book), “Chapter 3 · file page 57” until then, and “Chapter 3 · location 57” for an EPUB, which has no printed pages (the number is the place in the reading copy; no printed page is made up). A hit on a page shared by two chapters is named by the later one. Also: the count badges in the sidebar now meet the AA contrast limit on the highlighted item.
- **Books.** A new **Books** tab in the Library keeps your academic books, PDF and EPUB. Press ＋ Add a book or drop the files on the Library: you check the details first (title, authors, publisher, year, ISBN, DOI), taken from the file itself (an EPUB carries them) and looked up in Open Library and Crossref. A PDF dropped anywhere can be switched between Paper and Book; a PDF dropped on the Books tab starts as a book; an EPUB is always a book. The reader shows an EPUB as pages made from it (the chapters become the outline, and your EPUB is kept as it was beside it). A book is searched, highlighted, noted, put in folders and asked about like a paper, and “In the books” searches the words inside them; it is not listed among the papers. A copy-protected (DRM) EPUB cannot be read and is refused with a plain message. A book already in the library (same ISBN, DOI or title) is recognised and not added twice. Books are never summarised by themselves. Chapters: see the next entries.
- **Using the app on two computers with one data folder (Dropbox).** Put the data folder in Dropbox, install the app on the second computer and choose the same folder, and it starts where the first stopped. To make that safe:
  - What belongs to one computer no longer sits in the data folder: the browser used for library sign-ins (and its cookies), the search index, the language model, caches, update state, staged PDFs and the lock that says a dashboard is running. They live in `~/Library/Application Support/Journal Watcher/local/`. An earlier copy in the data folder is moved there the first time; you sign in to your library again once on each computer. Run history, screening memory, the AI spending record and backups stay in the data folder, so both computers share them.
  - **Settings → Computers & sync** shows this computer's name (you can change it), the other computers that have used the folder (and which have it open right now), and the copies Dropbox had to make when both computers changed the same file (“… conflicted copy …”). For the library list (`_index.csv`) “Join the two lists” keeps every paper of both copies; any copy can be set aside into `Papers/_conflicts/` (nothing is deleted). A note appears in the top bar when the folder is open on another computer or a conflicting copy exists.
  - **API keys can live in this Mac's Keychain** instead of the `.env` file in the data folder: a key you paste is saved there from now on, and “Move them to the Keychain” (Settings → Computers & sync) moves the keys already in the file, checking each one reads back before its line is removed. You paste each key once on each computer. Dropbox keeps earlier versions of files, so after moving, create new keys at your AI providers and delete the old ones.
- **Adding your own PDFs now shows you what was found before anything is filed.** Drop PDFs on the Library, on the Folders page, on a folder or inside an open folder (or use ＋ Add paper → choose a file) and one dialog opens with a card per PDF: the DOI and title the PDF itself carries are looked up on Crossref, up to three matching records are listed (each marked as matching the PDF's first pages or not), and the title, authors, journal, date and DOI are boxes you can correct. You choose where it goes (Library only, a folder, a new folder; fixed to the folder when you dropped on one). Nothing is filed until you press Add; Cancel, Escape or unticking a PDF throws it away. A paper you already have is flagged and not added twice. The note in the index says whether the details came from Crossref, from Crossref edited by you, or were typed by you.
- Settings → AI & privacy is tidier. In the Providers table each key box now sits on one line with its Save key button, the columns have fixed widths and every row has the same height; in “Which model does what” the provider, model and effort boxes are no longer cut off (“anth”, “lo”, half a model name); Test results appear under their button instead of beside it. In a narrow window the tables scroll inside their card.
- The name of the AI model is no longer shown under the app's name at the top of the sidebar.
- Settings → AI & privacy has a **“Use one for everything”** row: pick a provider and a model once, press “Apply to all features”, then Save, instead of changing every feature one by one. It starts from what most features use now, shows how they are split, leaves the effort and the embeddings alone, and leaves the Ideas Lab’s current events as it is when the provider you picked cannot search the web. Any row can still be changed on its own, and the row has its own Test button.
- The AI settings are now one **AI** tab with three pages under it: AI & privacy, Usage & cost and Prompts. That leaves seven tabs in Settings, which fit in one row at ordinary window sizes (a narrower window scrolls the row sideways instead of dropping the last tab onto a second line). Opening Settings → Usage & cost, from a link or the command palette, works as before, and coming back to the AI tab returns to the page you were on.
- Pasting an API key is more forgiving: the `NAME=` of a whole `.env` line (for example `OPENROUTER_API_KEY=sk-or-…`), a leading “Bearer”, quotes and invisible characters are removed, and the page says what was tidied. A key that does not start the way that provider’s keys usually do (OpenRouter: `sk-or-`) gets a note, not a refusal. Before, a pasted `NAME=key` line was saved as it was and the provider answered 401 “User not found”.
- A provider that refuses the key now says what to do (“press Change on its row and paste the key again”) next to its own message, for 401 and 403 answers.
- A key you change takes effect at once. The app used to go on using the Anthropic key it had started with until it was restarted.
- **Indexing uses the whole computer.** Reading papers and books into the search index used little more than one core. The local model now embeds several small pieces of text at the same time (about one per core, twelve at most). Measured on a four-core test machine, 128 passages took 26.9 s before and 7.4 s now, and the numbers come out exactly the same, so search and Ask give the same results. The activity tray shows the speed while it works (“… · 17 passages/s on 4 workers”) and each paper's timing is written to a small log on this computer. A model that cannot be used from several threads falls back to one piece at a time.
- **The search index and the saved AI answers now travel with the data folder.** A paper or book is read into the index once, on whichever computer sees it first, and an AI answer paid for once is free on the other computer. Both can be made again, so a copy Dropbox makes of one of these files when two computers write at once is simply removed (it is not shown as a conflict), and vectors that do not fit the paper or the model are made again instead of being trusted. Settings → Computers & sync says how much space they use. Plan for it: a large library adds hundreds of megabytes to the folder. A copy of the index kept on this computer by the development versions is merged back into the folder once.
- **Your choices in the page follow you between computers.** The theme, the reader's mode and tab, list or grid, the order of the folders, the skim settings, the voice, whether the welcome guide was seen and **where you stopped reading each paper** are kept in `ui_prefs.json` next to your settings. A new computer starts with them, and the first time a browser that already had its own choices opens, they are added. The sidebar fold and the reader panel's width depend on the screen and stay on each computer. Where you stopped reading is sent in batches (and when the page closes), so reading does not keep Dropbox busy.

## 1.2.1

- In a search by terms every match is a download. “Screen with AI” no longer skips a paper that contains your term. It adds topics, the method and a relevance order, and the card says “AI said skip” when the AI would have left it out. Terms searches you already screened are shown this way too.
- Harvard Business Review can be searched by year, in archive searches and in Search terms. Journal Watcher reads the contents pages of HBR's print issues, which list each article's title, authors and a one-line summary. HBR's web-only articles are in no issue, so they still come only through the weekly check. HBR is off until you tick it.
- Fixed: the Skipped filter showed no papers, and its cards were piled up above the window, over the header.
- Fixed: off campus, one MIS Quarterly, JAIS or DSS paper could stop a whole download batch. Its publisher's own login page was taken for your library asking for a password, so your library sign-in was cleared and every later paper said “Needs library sign-in” without being tried.

## 1.2.0

- Watch has a third tab, Search terms. Type one or more terms (for example difference-in-differences, DiD), pick journals and years, and Journal Watcher lists every paper whose title, abstract or keywords contain any of them. It is free and needs no AI. Case, hyphens or spaces between words, and singular or plural are ignored. An acronym typed with capitals (DiD) does not match the ordinary word "did". “Screen with AI” can rank the matches against your interests afterwards.
- Settings has a new Paper sources tab for a free OpenAlex key, the email address Unpaywall asks for (open-access copies were never looked up without it), and an optional Elsevier API key.
- NBER and other searches no longer seem to hang. Without a key, OpenAlex gives everyone on a network one small shared daily allowance. When it was used up, every call waited about a minute and a half. Now the app goes on at once, and abstracts are fetched 50 at a time (an NBER year in seconds with a key, about half a minute without).
- Settings → Library access can find your library's settings for you. Paste your library's web address (or any database link from its site). Journal Watcher reads a few of its pages and finds its OpenAthens domain, EZproxy address or EBSCO start page. It shows where it saw them and checks an OpenAthens domain with OpenAthens itself. A pasted go.openathens.net link, a web site without https:// or a whole EZproxy link is now tidied instead of refused.
- Library sign-in and "Test my access" now go to a publisher page (ScienceDirect) through your library. Before, they opened the library's own web site, which OpenAthens lets anyone through to, so the app could say "Signed in" when no sign-in had happened. A sign-in now counts only when the way went through your university's sign-in. A wrong OpenAthens domain is reported at once.
- OpenAthens and EZproxy now cover campus and home together. On campus papers come by network address as before. Off campus a paper the publisher refuses is asked for through your library, whatever the sign-in tick says, because your university's single sign-on often still lets you in. If your library asks for a password, the rest of that batch says "Needs library sign-in" instead of waiting.
- Your library's EBSCO (for example Business Source Ultimate) can be used again. When it is set up, a paper the publisher did not give is looked for there.
- Downloads keep a careful pace. Papers from the same publisher are spaced out (about 45 s for sites with “verify you are human” checks such as ScienceDirect, 20 s for others, with some randomness), and twice that for a site that has already asked for a check in the batch. While it waits, Journal Watcher writes the summaries of the papers it already has. Settings → Library access → Download pace offers Normal and Fast too.
- “Ready to read”: in the Library, a green bar beside a paper means its AI summary is written and the paper is ready to explore. A key under the journal's name (and above search results and folder lists) says what the bar means and how many papers have it.
- The Mac app no longer shows a bare `{"error": "not found"}` when another copy of Journal Watcher (for example one started from Terminal) already uses your data folder. It says which copy, whether it answers, and offers Try again or another folder.
- An About page (sidebar → About): who makes Journal Watcher, with the author's university and links, what the app is and how it is licensed, and a way to chip in for a coffee.
- A small reminder card that Journal Watcher is free and takes tips, after 14 days and 5 visits, at most three times and weeks apart. It never appears while you read, while the AI works or over Settings; "Don't ask again" and a switch under About end it. The app only counts, on your own computer, how often you open it: nothing is sent anywhere.
- Update notices can be verified against the author's digital signature (Settings → About & updates says whether this copy does): a feed without a good signature is ignored, and nothing is installed from it.
- Fixed: in the reader, the page number showed the page above after you jumped to a page, and zooming (or Fit, or going back after following a link) moved the text you were reading by about a hundred pixels each time. The text now stays where it was, in the collapsed view too (also when the line you are reading falls on a "lines hidden" bar).
- Fixed: a cell you had started editing in the comparison matrix was lost when a fill finished. Cells now wait until the fill is done.
- Fixed: a download could store a different paper's PDF under the paper's name (for example when a publisher's page linked a cited paper's PDF). Every download is now checked against the paper: its DOI, or its title and authors, must be on the first pages of the PDF. A PDF that is another work is refused (the paper stays in the download queue as “Wrong PDF refused”, with the reason on hover, and no summary is paid for) and the other routes are tried. A PDF the app cannot read, such as a scan, is kept and marked “Identity not checked”. Files already in your library are not rechecked.
- Fixed: Settings → About & updates said “You have the newest version” next to a red “HTTP Error 404: Not Found”. It now says what happened in plain words: “No update found yet” (calm, not red, before the first update is published), or that the update server can’t be reached, is busy, refused the request, or sent something that is not an update, or that an update’s signature did not check out. “You have the newest version” appears only after a look that worked, “Haven’t looked for updates yet” before the first one, and the exact error is under “Details”. A check started from the Help menu updates the open card, and changing the update address no longer shows the old address’s result.
- On a large screen the pages use the window: above 1500 px wide the Watch, Library, Folders and Settings columns grow with the window (up to 2200 / 2400 / 1800 px) instead of staying a 1200 px column between empty margins, paragraphs keep a readable line length, and the Settings heading lines up with its cards. Below 1500 px nothing changes. The text size is unchanged; a text-size setting is planned separately.
- Settings → Library access has a “Test my access” button. It opens your library’s page in the background with your saved sign-ins and says what it saw: signed in (the Sign-ins row turns green), asked for a password (the green tick is taken away), a human check, or a page that says nothing (and that this is not proof you have no access). Also fixed there: the “Saved.” message vanished at once, a typed OpenAthens domain was ignored unless you had also chosen its option, and the sign-in window waited for a password when you were already signed in.
- Archive searches are remembered. Pressing Search for a search you already ran continues that saved search (its papers, verdicts and downloads stay; nothing is screened or paid for again), and the form says so first. A paper that was already judged for the same question (topics, method, focus phrase) and the same text keeps its verdict in any later search, for as many days as you set in Settings → AI & privacy (default 90; 0 = always ask again). A journal's year range is kept for a week (a day when it includes this year), so searching again does not wait for the journals. “Search again…” fills the form with a past search’s settings, “Pick up where you left off” lists your last runs when nothing is open, and the Past runs list opens on the kind you last used.
- Settings → AI files & backup has “Check my PDFs”: it reads the first pages of every PDF in your library and lists the ones that are not the paper they are filed under (the title the PDF carries is shown), so a wrong file stored by an earlier version can be found. For each you can look at it, say “it is the right paper”, or “Remove and download again”: the PDF and its notes, highlights and summary are moved to `Papers/_removed/` (nothing is deleted) and the paper is queued for download again. PDFs it cannot read (scans) are listed separately; nothing changes until you choose.
- Downloads use your university: when a publisher asks for a login and your library is set up as OpenAthens or EZproxy (Settings → Library access) and you are signed in to it, the paper’s page is asked for again through your library’s sign-in. If your library session has ended, or you have not signed in to it, the paper says “Needs library sign-in” and offers the button. Nothing changes for the other library options (each publisher’s own page, VPN, none) or for INFORMS and AIS papers, which keep asking for your membership sign-in.
- SSRN can be searched: in Search archive, SSRN is a choice among the journals (off by default). It is searched by words, so it needs a focus phrase, and only the 200 best matches are looked at, screened like any other paper. Its papers are downloaded from their SSRN page (the page’s own download link is followed; an SSRN tab opens in “Other publisher sites” so you can sign in).
- Screening new papers now counts against your monthly budget. It used to call the model directly, so the budget did not stop it and its cost was missing from Settings → Usage. Now it goes through the same AI layer as everything else: it is listed there as “screen”, its model is set in Settings → AI (“Screening new papers”; Claude Sonnet 5.5 unless you change it) and local-only mode applies to it. When the budget is used up the search stops, the papers not yet screened stay as they are (they are not marked as failed), and searching again screens only those; papers judged earlier are kept.

## 1.1.0

- Sign-ins show what state they are in: a green tick and "Signed in · 3 h ago" for each one that worked, a "waiting for you" row while a window is open, and a green dot on the Sign-ins button. The browser window itself shows a green tick before it closes.
- Library access for any university: Settings → Library access (OpenAthens, EZproxy, or each publisher's own "sign in through your institution" page). No institution is built in any more.
- The Sign-ins menu stays usable while a sign-in window is open.
- Sign-in problems now say why (for example when the app's browser could not start) instead of "wasn't completed".
- Open-source repository layout: your data stays in your data folder; starting settings come from `defaults/`.

## 1.0.0

- First public release: weekly journal watch with AI screening, a library, a PDF reader with highlights, notes and Ask, folders with matrix / ideas / related-work tools, flashcards.
- Light-first design with a sidebar; a lighter dark theme.
- Mac app with a drag-to-Applications installer and update notices ("Update now").
- A welcome guide for first-time users: AI keys and sign-ins explained.
- Library access for any university (OpenAthens, EZproxy, or each publisher's institution login), with a green tick for every sign-in that worked.
